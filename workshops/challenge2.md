# コードからドキュメントの詳細を把握する

このアプリケーションがどのようなものかを大体把握することができました。  
次はアプリケーションの詳細な情報を把握していきます。  
いわゆる詳細設計などで取り扱われる領域の情報を把握したいのですが、この情報は図などを利用したほうがレビューを実施しやすいです。  
Markdownを利用するうえでデファクトに近い [`mermaid.js`](https://mermaid.js.org/) を使用してドキュメントを構成します。  
mermaidは VS Code拡張の [Markdown Preview Mermaid Support](https://marketplace.visualstudio.com/items?itemName=bierner.markdown-mermaid) があればきれいに見ることが可能です。

``` markdown
アプリケーションの詳細を確認するためのドキュメントを作成します。
作成したドキュメントは `docs` に格納してください。既存の資料に追記したほうが適切な場合はそのようにしてください。
ドキュメントを作成した場合はルートディレクトリnoREADME.mdにIndexを作成してください。
ドキュメントは長大になることを防ぎたいので大項目ごとにファイルを分離してください。  
図示するほうが適切な場合はmerimaid記法を使用してドキュメントを作成してください。

下記のドキュメントを作成します。一覧はテーブル形式で記載してください。
<!-- 以下自由に調整可能 -->
- 画面遷移図
  - 機能ごとに記載してください
- ユースケース図
  - 機能ごとに記載してください
- 画面一覧
  - URLパス、提供されている機能の概要を記載してください
- 画面の項目一覧
  - 下記項目を一覧で記載
    - 論理名、物理名、初期値、必須有無、フォーマット有無、読み取り専用有無、最小最大文字数、Validation
- 画面・API処理毎のフロー図
- メッセージ一覧
  - メッセージ種別（エラー/ガイド）、表示メッセージを記載してください
- テーブル情報
  - テーブル一覧
    - 論理名、物理名、テーブル概要
  - テーブルの項目一覧
    - 論理名、物理名、項目概要、型、備考（特記すべきことあれば）
  - ER図
- WebAPI仕様
  - OpenAPI仕様のJson
  - IF仕様
    - IF名、パラメータ名（物理、論理）、必須、文字列長などの制限有無を記載
```
